# FragCity — Product Requirements

> نسخهٔ 1.0 برای مرحلهٔ کشف و PoC — ۱۶ اکتبر ۲۰۲۶  
> وضعیت این سند: مبنای نیازمندی‌ها؛ بخشی از جزئیات تجاری هنوز تصمیم نهایی می‌خواهد.

## 1. چشم‌انداز

ساخت سکوی میزبانی سرور CS2 که بخش عمدهٔ مدیریت سرور و فروش را به محصولات متن‌باز تخصصی بسپارد و توسعهٔ سفارشی FragCity را به منطق تجاری، یکپارچگی‌ها و شکاف‌های واقعی محدود کند.

## 3. مدل مالی تأییدشده

### 3.1 خرید و مدت اعتبار

- مشتری ابتدا کیف پول را شارژ می‌کند.
- برای خرید بسته، قیمت ثابت آن بسته یک بار کسر می‌شود.
- شروع اعتبار به زمان تأیید موفق خرید وابسته است، نه زمان کلیک اولیه.
- مدت بسته حتی زمانی که سرور خاموش است ادامه دارد.
- زمان انقضا به‌صورت timestamp و ترجیحاً UTC ذخیره می‌شود.
- این سیستم **صورتحساب مبتنی بر uptime یا مصرف دقیقه‌ای نیست**.

### 3.2 سیاست‌های باز

| موضوع | پیشنهاد اولیه | وضعیت |
|---|---|---|
| تعریف ۱ روز | ۲۴ ساعت از زمان شروع بسته، نه تا نیمه‌شب | پیشنهاد؛ تأیید نهایی لازم است |
| تمدید قبل از انقضا | افزودن مدت جدید به انقضای فعلی | پیشنهاد |
| خرید بعد از انقضا | شروع اعتبار جدید پس از خرید موفق | پیشنهاد |
| انقضا | ابتدا Suspend/Stop؛ حذف فایل‌ها فوری نباشد | پیشنهاد امنیتی |
| مهلت نگهداری بعد از انقضا | یک بازهٔ مشخص برای بازیابی | تصمیم لازم |
| شکست Provisioning بعد از Debit | Retry قابل ردیابی یا عملیات جبرانی/Refund | اجباری، جزئیات پیاده‌سازی Pending |
| خرید هم‌زمان از چند درخواست | کنترل تراکنشی موجودی و idempotency | اجباری |

## 5. نیازمندی‌های زیرساخت

### محیط موجود
- میزبان: Windows، AMD Ryzen 5 8400F، رم ۱۶ GB DDR5-5600.
- آزمایش Linux: Debian 13 روی VMware؛ ۴ vCPU و حدود ۶ GiB رم اختصاص‌یافته در وضعیت ثبت‌شده.
- اینترنت و IP ثابت میزبان طبق گزارش کاربر موجود است.
- سایت و MariaDB در حال حاضر روی هاست اشتراکی cPanel هستند.
- Remote MariaDB روی TCP/3306 برای اتصال خارجی در سرویس فعلی قابل استفاده نیست؛ مسیر جایگزین HTTPS API است.
- هدف شروع ۵ سرور پایدار؛ ۸ تا ۱۰ سرور هدف کششی و مشروط به آزمون است.

### نیاز استقرار
- محیطی که امکان اجرای سرویس‌های پس‌زمینه، نصب Docker/Wings و تنظیم شبکه/فایروال را بدهد.
- هاست اشتراکی فعلی را بدون تأیید قابلیت‌ها، محل مناسب Panel/Wings یا Worker دائمی فرض نکنیم.
- برای نود بازی، پورت‌های ترافیک بازی جدا از پورت‌های سایت/HTTPS برنامه‌ریزی شوند.
- هر نود شناسه، نام، ظرفیت، محدوده پورت و تنظیمات اختصاصی داشته باشد.

## 6. موارد خارج از محدودهٔ فعلی

- بازنویسی کامل Agent به زبان دیگر پیش از آزمون محصولات آماده.
- ساخت Instance Maker یا RCON اختصاصی جدید، وقتی پنل منتخب آن قابلیت را پوشش می‌دهد.
- بازکردن عمومی MariaDB روی اینترنت برای دورزدن محدودیت cPanel.
- راه‌اندازی پرداخت واقعی قبل از آزمون idempotency و صحت مالی.
- هرگونه تغییر در `cs2-kus-addons` بدون درخواست صریح جداگانه.

## 7. Definition of Done برای پایلوت

پایلوت فقط زمانی اجازه دارد به مشتری واقعی برسد که خرید و تمدید بسته، انقضای خاموش‌بودن سرور، کسر یک‌باره، جبران شکست Provisioning، جداسازی مشتریان، کنترل API، Backup/Restore، قطع شبکه، retry و rollback با شواهد ثبت‌شده قبول شده باشند.
